# 코인 자동매매 시스템

이동평균선(MA) · 지수이동평균선(EMA) · 변동성 돌파 · RSI 전략과, 손절/익절/매수금액 조절/일일 손실 한도 같은 **리스크 관리**를 갖춘 코인 자동매매 봇입니다.
코딩을 몰라도 `config.yaml` 한 파일의 숫자만 바꿔서 쓸 수 있게 만들었습니다.

> ## ⚠️ 먼저 읽어주세요
> * 이 프로그램은 **수익을 보장하지 않습니다.** 기본 설정값은 *사용법을 보여주는 예시*이지, 검증된 수익 전략이 아닙니다.
> * 코인 투자는 원금 손실이 날 수 있습니다. **잃어도 괜찮은 금액으로만** 하세요.
> * 순서는 반드시 **① 백테스트 → ② 모의투자(몇 주) → ③ 아주 적은 금액으로 실전** 입니다.
> * 거래소 API 키에는 **출금 권한을 절대 주지 마세요.**

## 1. 설치 (처음 한 번)

1. **파이썬 3.10 이상**을 설치합니다. (https://www.python.org/downloads/ — Windows는 설치 화면에서 *"Add Python to PATH"* 체크)
2. 이 저장소를 내려받고, 그 폴더에서 터미널(Windows: PowerShell, Mac: 터미널)을 엽니다.
3. 필요한 프로그램을 설치합니다.

```bash
pip install -r requirements.txt
```

## 2. 5분 안에 써보기

```bash
python main.py backtest --demo     # ① 인터넷 없이 가짜 데이터로 연습 (사용법 익히기용)
python main.py backtest --chart    # ② 진짜 과거 시세로 백테스트 (+ results/ 폴더에 그래프)
python main.py compare             # ③ 4가지 전략을 같은 조건으로 한눈에 비교
python main.py check               # ④ 설정과 거래소 연결 점검
python main.py run                 # ⑤ 모의투자 시작 (실제 시세, 가상 체결 — 돈 안 나감)
python main.py status              # 봇이 지금 뭘 들고 있는지 확인
```

백테스트 결과에서 볼 것:
* **총 수익률**과 **"그냥 보유"** 비교 — 그냥 들고 있는 것보다 못하면 굳이 봇을 쓸 이유가 없습니다.
* **최대 낙폭(MDD)** — 중간에 자산이 최대 몇 % 빠졌는지. *이 정도 하락을 실제로 견딜 수 있는지* 자문해보세요.
* 거래 횟수가 너무 적으면(예: 5회 미만) 결과를 믿기 어렵습니다. 기간을 늘려보세요 (`--days 730`).

## 3. 전략 고르기 (`config.yaml` 의 `strategy`)

| 이름 | 매수 | 매도 | 어울리는 상황 |
|---|---|---|---|
| `volatility_breakout` | 가격이 **오늘 시가 + k × 어제 변동폭**을 넘으면 | 캔들이 끝날 때(일봉이면 다음 날 시작) | 추세가 강하게 나오는 장 |
| `ma_cross` | 단기 이동평균이 장기 이동평균을 **위로** 뚫을 때(골든크로스) | 단기가 장기 **아래**로 내려가면(데드크로스) | 큰 추세장 (횡보장에선 손실 잦음) |
| `ema_cross` | 위와 같되 최근 가격에 더 민감한 지수이동평균 | 〃 | 〃 (조금 더 빠르게 반응) |
| `rsi_reversion` | RSI가 과매도(기본 30 미만)일 때 | RSI가 회복(기본 55 이상)되면 | 하락 후 반등을 노리는 방식 |

* `trend_filter_ma`: "직전 종가가 N일 이동평균 **위일 때만** 새로 매수". 하락장에서 매수를 피하려는 용도입니다. (0 = 끔)
* 전략별 숫자(`k`, `fast`, `slow` …)는 `strategy_params` 에서 바꿉니다.
* 숫자를 바꿀 때마다 `python main.py backtest` 로 결과를 확인하세요. 단, **과거에 딱 맞게 숫자를 맞추면(과최적화) 미래에는 안 맞는 경우가 많습니다.** 기간을 바꿔서도 비슷하게 나오는지 보세요.

## 4. 리스크 관리 (`config.yaml` 의 `risk`)

| 설정 | 의미 |
|---|---|
| `max_position_pct` | 한 번에 전체 자산의 최대 몇 %까지 매수할지 |
| `risk_per_trade_pct` | **손절에 걸렸을 때 자산의 몇 %만 잃을지.** 봇이 이 값에 맞춰 매수 금액을 자동으로 줄입니다 |
| `stop_loss_pct` | 매수가 대비 -N% 에서 손절 |
| `take_profit_pct` | 매수가 대비 +N% 에서 익절 (0 = 끔) |
| `trailing_stop_pct` | 매수 후 최고가 대비 -N% 떨어지면 매도 (0 = 끔) |
| `max_daily_loss_pct` | 하루 손실이 자산의 N% 에 닿으면 그날은 신규 매수 중단 |
| `max_drawdown_pct` | 자산이 최고점 대비 -N% 가 되면 **전량 매도하고 봇 정지** |
| `max_trades_per_day` | 하루 최대 매수 횟수 |
| `cooldown_candles` | 손절 후 N 캔들 동안 재매수 금지 |

**예시:** 자산 100만 원, `stop_loss_pct: 3`, `risk_per_trade_pct: 1` → 봇은 약 33만 원어치만 사고, 손절에 걸려도 손실은 약 1만 원(자산의 1%)으로 제한됩니다.

`0` 으로 두면 해당 기능이 꺼집니다. 잘못된 항목 이름이나 범위를 쓰면 실행 시 어디가 틀렸는지 알려줍니다.

## 5. 실전 매매 전 체크리스트

1. 백테스트에서 결과가 납득되는가? (수익률 + MDD + 거래 횟수)
2. `python main.py run` **모의투자를 최소 2~4주** 돌려보고 `logs/trades_paper.csv` 를 확인했는가?
3. 거래소에서 **API 키 발급** — 권한은 *자산조회 + 주문*만, **출금 ✗**, 허용 IP를 내 컴퓨터/서버 IP로 제한
4. `.env.example` 을 `.env` 로 복사하고 키를 입력 (`.env` 는 GitHub에 올라가지 않습니다)
5. `config.yaml` 의 `capital` 을 **정말 잃어도 되는 소액**으로 설정 (봇은 계좌에 돈이 더 있어도 `capital` 안에서만 거래합니다)
6. `python main.py check` 로 키/잔고 확인 → `python main.py run --live` → 안내에 따라 `실전` 입력
7. (선택) 텔레그램 알림: `.env` 에 `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` 입력

**멈추는 법:** `Ctrl+C` 또는 폴더에 `STOP` 이라는 빈 파일 만들기 (STOP 은 새 매수를 막고, 보유분이 정리되면 봇이 종료됩니다).
**봇이 스스로 멈추는 경우:** 최대 낙폭 도달, 주문 결과를 알 수 없는 오류(중복 매수 방지), 거래소 계좌에 기록상 코인이 없는 경우. `python main.py status` 에 이유가 표시됩니다. 원인을 확인한 뒤 `state/` 폴더의 해당 파일을 지우면 처음 상태로 다시 시작합니다.

**24시간 돌리기:** 봇은 컴퓨터가 켜져 있고 인터넷이 연결되어 있어야 동작합니다. 노트북이 절전 모드에 들어가면 멈춥니다. 상시 운영은 보통 클라우드 서버(VPS)를 씁니다. 껐다 켜도 `state/` 에 저장된 보유 상태를 이어받습니다.

## 6. 알아둘 한계 (솔직하게)

* **실제 거래소 연결은 제 개발 환경에서 검증하지 못했습니다.** 개발 환경에서 거래소 서버 접속이 막혀 있었습니다. 전략·리스크·봇 로직은 자동 테스트 70개로 검증했고 (특히 *같은 데이터에서 백테스트와 봇이 똑같이 매매하는지*까지 비교), 주문 코드는 가짜 거래소 객체로만 시험했습니다. 그래서 **처음에는 반드시 `check` → 모의투자 → 소액 실전** 순서로 확인해주세요. 거래소별 특성(업비트의 시장가 매수 방식 등)에서 조정이 필요하면 `python main.py --debug ...` 결과를 Claude 에게 보여주세요.
* 백테스트는 과거 일을 가정한 계산입니다. 수수료·슬리피지를 넣었지만 실제 체결은 더 불리할 수 있고, 특히 **실전의 손절은 10초 간격 확인 후 시장가 주문**이라 백테스트(정확히 손절선에서 체결 가정)보다 더 나쁘게 체결될 수 있습니다.
* 일봉 기준 업비트의 하루는 **오전 9시(KST)** 에 시작합니다. 변동성 돌파는 이 시각에 매도/신규 매수가 일어납니다.
* 현재는 **현물, 한 번에 코인 하나, 매수 후 매도(롱 전용)** 만 지원합니다.
* 거래소 점검·네트워크 장애 시 봇은 재시도합니다. 하지만 이때 손절이 지연될 수 있습니다.

## 8. 폴더 구조

```
config.yaml        ← 여러분이 고치는 설정 파일 (유일)
main.py            ← 명령어 진입점
.env               ← API 키 (직접 만듦, GitHub에 안 올라감)
trader/
  strategies.py    ← 매수/매도 전략 (새 전략은 여기에 추가)
  risk.py          ← 리스크 관리
  backtest.py      ← 백테스트 엔진
  bot.py           ← 모의투자/실전 봇
  broker.py        ← 주문 실행 (모의 / 실전)
  data.py indicators.py config.py notify.py
tests/             ← 자동 테스트 (python -m pytest, 먼저 pip install pytest)
logs/              ← 실행 기록과 거래 내역 CSV (자동 생성)
state/             ← 봇이 기억하는 상태 (자동 생성)
results/           ← 백테스트 결과 (자동 생성)
```
